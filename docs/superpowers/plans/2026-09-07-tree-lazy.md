# Tree lazy subtrees

Actual chat uses nested row lazy values and extra copy-selection dependencies;

cached wire data alone.

## Required behavior

- Preserve the existing checked dependency/revision/by-key lowering, hoisted
  component routing context and immutable dependency snapshots. Unchanged state
  revisions must avoid dependency cloning and builder execution, not merely hide
  their output behind a cache. Theme and reconciliation scope remain keys.
- Cache wire subtrees per running guest and concrete expression/scope. Nested
  lazy calls and equal keys in separate rows/drivers stay independent. Replace
  stale dependency versions at a site; cap parked entries like native memo_lazy.
- Cache hits restore callable event routes, including messages and typed handlers.
  The existing per-frame tables are cleared before view, so a cached numeric index
  alone is invalid. Ordinary routes must remain deterministic so unrelated frames
  do not force patches simply because a counter advanced.
- Add a wire lazy boundary carrying copied child data and a cache generation.
  Host rendering must reuse existing memo_lazy for element/layout memoization and
  unmount parking. Limits changes, virtual scroll viewport synchronization,
  inherited button ink, registered surfaces and theme changes still work.
- Isolate native parked lazy state by host instance as well as expression/scope.
  Wire keys/site IDs alone collide between two copies of the same app. An instance
  namespace must persist across host frame clones and change on a fresh instance.
- An evicted guest entry rebuilt with the same dependency gets a fresh generation:
  its newly allocated routes cannot reuse a native element with older callbacks.
  Removed routes must not remain callable after a frame stops referencing them.

## Implementation direction

Reuse the native lazy code generator's dependency tuple and builder; branch only
at the runtime helper and skip native outlining for Tree where necessary. The
Tree emitter lets Lazy reach this shared lowering. __IceElement is already a
wire Node alias on Tree.

Store a memo cache on Driver and activate it while rendering. Do not use one
process-global cache shared by independent Drivers. Make cached route entries
shareable (Rc<dyn Any>) and snapshot/restore them together with the node. A
separate cached-route ID range leaves current ordinary positional slots unchanged;
monotonic cached IDs prevent aliasing after rebuild/eviction. Nested builders must
not hold RefCell borrows across calls. Bound entries and release cached payloads
outside borrows. Frame-active route tables only contain currently reachable routes.

On the host, clone the existing retained rendering inputs into the memo builder,
as responsive already does. Use the native memo_lazy rather than implementing a
second layout cache. Add traversal/sanitization/diff and malformed-frame handling
for the wire boundary. Host memo generations are scoped by instance identity.

retain their thread-local lot; module rendering will opt into the owned lot.
